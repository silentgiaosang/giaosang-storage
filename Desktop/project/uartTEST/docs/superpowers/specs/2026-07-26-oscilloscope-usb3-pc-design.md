# PC 上位机示波器 — 设计规格书

**日期:** 2026-07-26
**状态:** 设计已确认，待实现

---

## 1. 项目概述

基于 CH32H417 MCU + USB 3.0 的上位机示波器系统。MCU 负责 HSADC 高速采集并通过 USBSS（5Gbps）传输原始波形数据到 PC，PC 端（C# WPF）负责波形渲染、FFT 频谱分析和参数测量。

---

## 2. 目标规格

| 维度 | 参数 |
|------|------|
| 采样率 | 40Msps |
| 分辨率 | 10-bit（原样传输） |
| 通道数 | 单通道 |
| MCU→PC 接口 | USB 3.0 (USBSS)，Bulk 传输，自定义协议 |
| 采集模式 | 连续流模式 + 触发捕获模式，PC 端可切换 |
| 触发 | 基本边沿触发（上升/下降沿），50% 预触发深度 |
| 分析 | FFT、自动测量均在 PC 端执行 |
| PC 平台 | C# WPF，Visual Studio |

## 3. 通信协议

### 3.1 数据包格式（MCU → PC）

```
┌────────┬────────┬──────────┬──────────┬───────────┬────────┐
│ 同步头  │ 包序号  │ 模式标志  │ 数据长度  │  数据载荷   │ CRC16  │
│  2B    │  4B    │   1B     │   2B     │   N bytes  │  2B    │
│ 0xAA55 │ 自增   │ 0=连续流  │          │           │        │
│        │        │ 1=触发捕获│          │           │        │
└────────┴────────┴──────────┴──────────┴───────────┴────────┘
```

- 同步头：`0xAA 0x55`，用于包对齐
- 包序号：32-bit 自增，PC 端检测连续性，统计丢包
- 数据长度：载荷字节数（不含协议头），最大 65535
- CRC16：对数据载荷的 CRC-16-CCITT 校验

### 3.2 连续流模式载荷

1024 个 10-bit 采样点，打包为 `1024 × 10 / 8 = 1280` 字节（每 4 个采样点占用 5 字节：`[A9:2][B9:2][C9:2][D9:2][A1:0|B1:0|C1:0|D1:0]`）。A 为时间最早的采样点，所有多字节字段均为小端序（Little-Endian）。

### 3.3 触发捕获模式载荷

```
[触发信息头: 8B] [波形数据: 1024 采样点 × 10-bit = 1280B]
触发信息头:
  - 触发点索引: 2B (固定 512，即 50% 位置)
  - 触发边沿: 1B (0=上升, 1=下降)
  - 触发电平 ADC 值: 2B
  - 保留: 3B
```

### 3.4 命令包（PC → MCU）

通过 USB Bulk OUT 端点发送，固定 5 字节短包。

```
[CMD: 1B] [VALUE: 4B]
CMD 定义:
  0x01 = 切换连续流模式
  0x02 = 切换触发捕获模式
  0x03 = 设置触发边沿 (VALUE: 0=上升, 1=下降)
  0x04 = 设置触发电平 (VALUE: 12-bit ADC 值)
  0x05 = 设置采样率分频 (VALUE: 分频系数)
```

## 4. MCU 固件架构

### 4.1 模块划分

```
main.c
├── HSADC 初始化（40Msps, 10-bit, 乒乓缓冲）
├── USBSS 初始化（USB 3.0 设备枚举）
├── 命令解析（PC→MCU 控制包处理）
└── 主循环
    ├── [连续流模式] DMA 乒乓缓冲 → 打包 → USB Bulk 发送
    ├── [触发模式]  环形缓冲 → 边沿检测 → 截取 1024 点 → 打包发送
    └── 状态 LED 心跳
```

### 4.2 乒乓缓冲

- 双 1024 采样点 Buffer
- Buffer A 采集中，Buffer B 打包发送
- DMA 半满/全满中断驱动切换
- 目标是零丢点

### 4.3 触发模式

- 环形缓冲区持续采集
- 硬件/软件边沿检测
- 检测到触发条件后：取触发点前 512 + 后 512 = 1024 点，打包发送

### 4.4 错误处理

- USB 发送失败：丢弃当前包，序号不递增
- PC 端通过序号跳跃检测丢包
- 不复用重传机制（示波器数据实时性优先于完整性）

## 5. PC 端软件架构

### 5.1 工程位置

`D:\scope` — C# WPF 项目

### 5.2 模块架构

```
App (WPF)
├── UsbService — USB 通信线程
│   ├── LibUsbDotNet 驱动层
│   ├── 收包：同步头对齐 → CRC 校验 → 序号检查
│   └── 发包：命令包 → Bulk OUT 端点
├── DataBuffer — 环形缓冲
│   ├── 容量 64MB (~1.3s @40Msps 连续流)
│   ├── SpinLock 保护，单写多读
│   └── 满时循环覆盖最旧数据
├── WaveformRenderer — 波形渲染
│   ├── WriteableBitmap + 后台写入
│   ├── 水平压缩：每像素列取 min/max 画竖线
│   ├── 10 格垂直网格，每格对应电压档位
│   └── 连续流：滚动刷新 | 触发模式：静止 + 触发点标记
├── Analyzer
│   ├── FftProcessor — 频谱分析（Math.NET Numerics）
│   └── Measurer — 自动测量（频率/周期/峰峰值/平均值）
├── TriggerControl — 触发参数面板
├── MainViewModel — MVVM 数据绑定枢纽
└── MainWindow — 主窗口布局
```

### 5.3 线程模型

| 线程 | 职责 | 优先级 |
|------|------|--------|
| USB 接收线程 | 高速读包、校验、Push RingBuffer | 高 |
| 渲染定时器 | 60fps 取数据、波形渲染 | 中 |
| FFT 后台线程 | 按需执行 FFT，完成后 Dispatcher 回 UI | 低 |
| UI 主线程 | 响应用户操作、命令下发 | 正常 |

## 8. 技术风险

| 风险 | 缓解措施 |
|------|----------|
| USBSS Bulk 传输速率未达预期 | Phase 1 优先验证 USB 吞吐量 |
| 10-bit 打包/解包性能瓶颈 | 使用 SIMD 或预计算查找表加速 |
| WPF 60fps 渲染压力 | WriteableBitmap 后台写入 + 像素压缩 |
| MCU 乒乓缓冲与 USB 发送时序冲突 | 充分测试边界条件，加入状态机保护 |
